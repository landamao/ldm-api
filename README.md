# 🐱 懒大猫 API

一个 **单文件、开箱即用** 的模型聚合网关。把所有上游服务商的模型收拢到一个地址、一个密钥之下，
对外提供完全兼容 OpenAI 协议的接口。

- **一个可执行文件**：前端资源编译进二进制，不需要 Node、不需要数据库、不需要配置文件。
- **一个数据文件**：所有配置、密钥、日志都写进同目录下的 `data/ldmapi.db`。
- **跨平台**：Windows / Linux / macOS 均有预编译产物。

```
                     ┌──────────────┐
   OpenAI SDK ──┐    │              │   ┌── 渠道 A（OpenAI 兼容）
   curl ────────┼──▶│  懒大猫 API   │──▶├── 渠道 B（Anthropic）
   任意客户端  ──┘    │              │   └── 渠道 C（Google Gemini）
   一个密钥           └──────────────┘      自动协议转换 / 失败切换
```

## 快速开始

### Windows

```powershell
.\ldmapi-windows-amd64.exe
```

### Linux

```bash
chmod +x ldmapi-linux-amd64
./ldmapi-linux-amd64
```

启动后终端会打印控制台地址和一个可直接使用的 API 密钥：

```
  ╭──────────────────────────────────────────────────────────────╮
  │  🐱 懒大猫 API   v1.27.4                                     │
  │                                                              │
  │  控制台     http://127.0.0.1:6700                            │
  │  API 地址   http://127.0.0.1:6700/v1                         │
  │  数据文件   /opt/ldmapi/data/ldmapi.db                       │
  ╰──────────────────────────────────────────────────────────────╯
  ⚠ 管理端默认密码：landamao   请登录后立即在「系统设置」中修改
```

打开控制台 → 用 `landamao` 登录 → **先去「系统设置」改密码**。

### 命令行参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `-port` | `6700` | 监听端口 |
| `-host` | `127.0.0.1` | 监听地址；需要局域网/公网访问时显式传 `0.0.0.0` |
| `-data` | 可执行文件同级的 `data/` | 数据目录 |
| `-password` | — | 启动时重置管理端密码 |
| `-open` | `false` | 启动后自动打开浏览器 |
| `-version` | — | 打印版本号 |

> 可执行文件所在目录不可写时（例如放在 `/usr/local/bin`），数据会自动落到 `~/.ldmapi/`。

### 环境变量与 .env

除了命令行参数，也可以用环境变量配置。程序启动时会自动读取 `.env` 文件：先看当前工作目录，再看可执行文件所在目录；也可以用真实环境变量 `LDMAPI_ENV_FILE` 指定其它路径（这个变量不能写在 `.env` 里）。

优先级从高到低：**命令行参数 > 真实环境变量 > `.env` > 默认值**。

| 环境变量 | 对应参数 | 说明 |
| --- | --- | --- |
| `LDMAPI_HOST` | `-host` | 监听地址 |
| `LDMAPI_PORT` | `-port` | 监听端口 |
| `LDMAPI_DATA` | `-data` | 数据目录；相对路径以启动时的工作目录为准 |
| `LDMAPI_PASSWORD` | `-password` | 启动时把管理端密码重置为该值（至少 6 位；这里填密码本身，不是开关） |
| `LDMAPI_OPEN` | `-open` | `1`/`true`/`yes`/`on` 视为开启 |
| `LDMAPI_DEV` | — | 前端资源目录，开发时使用（如 `web`） |
| `LDMAPI_ENV_FILE` | — | 指定要加载的 `.env` 路径 |

`.env` 示例（完整模板见仓库里的 [.env.example](.env.example)）：

```ini
LDMAPI_PORT=6700
LDMAPI_DATA=/opt/ldmapi/data
```

`.env` 支持 `KEY=VALUE`、`export KEY=VALUE`、`#` 注释、单引号原样值和双引号转义（`\n`、`\t`、`\"`、`\\`），不支持多行值和变量展开；同一个变量写多次时以最后一次为准。密码里包含空格或 `#` 时建议用引号包起来。

`LDMAPI_PASSWORD` 每次启动都会把密码重置为该值（与当前密码相同时跳过，不会让已登录会话失效）。它会以明文保存在文件里，注意权限（`chmod 600 .env`）；仓库的 `.gitignore` 已忽略 `.env`，不要把它提交到版本库。

## 核心概念

### 渠道（Channel）

一个上游服务商。渠道 ID 唯一，**不能包含 `/`**，它会成为模型名的前缀。

在「渠道管理」里填的是**上游真实的模型名**（`a`、`b`、`c`），这里不做任何改写。
只有接入到「模型管理」之后，每个模型才会获得一个带渠道前缀的 ID。

```
渠道管理里填写：
  A:  a, b, c
  B:  a, b, d

模型管理里出现：
  A/a、A/b、A/c、B/a、B/b、B/d
```

添加渠道时**接口地址是必填的**，并且必须带上 `https://` 或 `http://`。网关不会在地址留空时替你
回退到官方 API——填错或漏填会导致请求静默打到错误的地方，这类问题很难排查，所以这里直接拒绝保存。

填好地址和 API Key 后，点「获取模型列表」就能直接拉取该服务商支持的模型，**不需要先保存渠道**；
拉取后可以在弹窗里勾选要加入或保留的模型，手工填写但上游未返回的模型会单独列出，模型列表本身也可以留空，先把渠道建好、之后再回来补。

一个渠道可以配置**多个 API Key**，但多 Key 模式默认关闭：关闭时只显示一个 Key 输入框和备注，
不显示「添加 Key」和「Key 调度」。在 API Key 右侧打开「多 Key 模式」后，才会出现多行 Key 表格：
左边「密钥」占 60% 宽度，右边「备注」占 40% 宽度；点「添加 Key」增加一行，点行尾的删除按钮移除整行。
旧数据只有一个 Key 的同样按关闭处理；已经配置多个 Key 的旧数据保持开启，不会丢配置。

已保存的 Key 以掩码显示。**修改备注时请求里只带该行的下标和新备注，不会重新提交密钥**；只有主动改写密钥列
才会替换 Key。清空某一行的密钥或删除整行即删除对应的 Key。关闭多 Key 模式只影响调度：请求始终只用第一个 Key，
其余 Key 保留在配置里不删除，重新打开开关即可继续使用；只有一个 Key 时也可以填写备注。
密钥和备注的前后空格都会被去掉。

多 Key 的调度策略：

- **顺序**：按配置顺序尝试；未开启亲和时始终从第一个可用 Key 开始。
- **随机**：每次请求把可用 Key 完整打乱后依次尝试。
- **Key 亲和**：上次成功的 Key 优先。顺序模式从它在配置里的位置开始顺延，其余 Key 保持原顺序；随机模式先试它，其余 Key 打乱后顺延。命中时调用日志的 Key 徽章右上角会显示橙色星标。
- **失败冷却**：只有上游**状态码**命中规则时才把该 Key 冷却，在设定时间内跳过（0 = 不冷却）。可在渠道的「Key 调度」里调整（支持 `400-430` 区间，输入框右上角可一键填入常用模板，模板为 401 / 403 / 408 / 429 / 5xx；留空表示任何状态码都不冷却 Key，未配置过的旧数据也按留空处理）。
- **超时和网络错误不冷却 Key**：连接失败、超时、断流、空响应都属于传输层问题，和 Key 本身无关，只影响本次尝试（仍会换 Key / 换路由重试），不会把 Key 记成冷却——否则一次网络抖动就会让整个渠道在冷却周期内不可用。
- **单 Key 不参与 Key 冷却**：Key 冷却是为了在多 Key 之间绕开坏 Key，单 Key 冷却只会把自己锁死；单 Key 失败由路由自身的失败冷却兜底。
- **全部冷却时重置**：所有 Key 都在冷却中时，自动清空该渠道的 Key 冷却，再按调度规则重试一遍（默认关闭）。

请求渠道模型时，先选定渠道模型，再按上述策略选择 Key；请求自定义模型时，先按模型路由选出渠道模型，
再在命中的渠道内选择 Key。某个 Key 返回的状态码命中渠道的「触发 Key 冷却的状态码」时，
会先在同渠道内换 Key；不在列表里的状态码仍会继续路由，但不冷却 Key。只有这条渠道的所有 Key
都失败后才继续下一条模型路由。渠道管理里的「测试连通性」会逐个尝试 Key，
任意一个可用即视为渠道可用。Multi-Key 的冷却和亲和状态只保存在当前进程内存中，重启后自然清空。

支持的渠道类型：

| 类型 | 适用服务 |
| --- | --- |
| **OpenAI 兼容** | OpenAI、DeepSeek、通义千问、月之暗面、智谱、Ollama、vLLM、OneAPI 等一切兼容 `/v1/chat/completions` 的服务 |
| **Anthropic** | Claude 官方 API（网关自动完成 OpenAI ⇄ Anthropic 双向协议转换） |
| **Google Gemini** | Google AI Studio / Gemini API（自动完成 OpenAI ⇄ Gemini 转换） |

接口地址默认会自动补全 `/v1`。如果服务商的版本前缀不是 `/v1`（例如火山方舟是 `/api/v3`），
把地址填到版本前缀（`https://ark.cn-beijing.volces.com/api/v3`），并关闭渠道编辑里的
「自动补全 /v1」；关闭后网关会按填写的地址原样拼接。

从渠道里移除模型名或删除渠道时，**不会自动改动「模型管理」里的配置**。网关会先列出仍然引用这些模型的渠道模型和自定义路由，由你选择「保留引用」或「一并移除」：删除渠道时可以只删渠道，模型配置保留并显示为不可用；也可以选择一起清理。这样可以避免编辑渠道时误删已经编排好的路由。选择保留的残留路由不会继续转发——渠道模型列表里已经没有这个模型名时，解析阶段会直接跳过它。

### 模型（Model）

**模型设置默认是空的**——即使已经配好了渠道，也必须在这里手动添加，模型才会对外开放。
这样做的好处是：渠道里可以放心地填几十个上游模型名，但只有你真正想开放的那几个会被调用到。

模型分两类：

| 类型 | 说明 |
| --- | --- |
| **渠道模型** | 直接暴露某个渠道下的某个上游模型，ID 形如 `A/a`。 |
| **自定义模型** | 自己起一个 ID（例如 `LDM`），按顺序路由到多个渠道模型。第一个失败（超时 / 限流 / 5xx）时自动切到下一个。 |

```
模型设置列表：
  渠道模型：  A/a、A/c、B/a、B/d
  自定义模型：LDM  →  A/c、B/d
```

调用 `LDM` 时，网关会先打 `A/c`；如果 `A/c` 挂了，请求会自动落到 `B/d`，调用方无感知。

自定义模型还支持：

- **路由策略**：顺序优先 / 轮询均衡 / 随机
- **路由分组**：相邻目标可以「合并」成组，组内每次按权重随机排序后依次尝试（权重越高越可能靠前，权重全部相等时等概率）
- **模型级超时**：每个模型单独设置超时（默认 300 秒）。非流式限制整次请求；流式限制「两段真实输出之间的最大空档」——首字到达后每收到一段正文、思考或工具参数就重新计时，模型持续吐字时总时长可以超过超时时间；心跳、只带 `role` 的空块、纯 usage 块都不算输出，不会给停滞的请求续命
- **强制流式请求**：在模型「高级设置」里开启后，对话类请求一律以流式请求上游。客户端要流式时行为不变；客户端要非流式时，网关用 `stream: true` 请求上游、自己把整条流收完（正文、思考内容、工具调用、用量都会保留）再按非流式 JSON 返回。这样可以只约束首字：超时时间内没有首字就判定这条路由失败，自动换下一条路由 / 下一个 Key，避免慢上游把非流式请求拖到整次超时。只对对话类端点生效，上游忽略 `stream` 直接回完整 JSON 时按普通非流式透传
- **模型亲和与失败冷却**：开启亲和后从上次成功的路由位置开始顺延；失败的路由进入冷却，冷却期间自动跳过
- **不可重试状态码**：在模型「高级设置」里配置（支持 `400-430` 区间，输入框右上角可一键填入模板）。命中后直接返回上游错误，不再尝试其它路由，也不记录 Key / 路由冷却；默认留空，表示所有状态码都可重试（未配置过的旧数据也按留空处理），模板 `400-428,430-499`（4xx 中除 429 外都不可重试）。401/403 在还有其它 Key 时仍会先换 Key
- **错误覆写**：在模型「高级设置」里填写状态码（400–599）和错误详情，标签旁的「?」可查看完整机制。只开总开关时，请求最终失败（上游报错、超时、无可用路由等）会用配置的错误替代原始错误，成功请求不受影响；再开「始终返回错误」则不请求上游，所有调用都直接返回配置的错误。「跳过不可重试状态码」默认开启，命中模型不可重试状态码的上游错误不参与任何覆写、原样返回；开启「始终返回错误」时本项不生效。子开关仅在总开关开启时可用。开「覆写为正文」后不再按错误返回，而是把错误详情当成模型正常回复、以 `200` 返回（流式按 SSE，非流式按 OpenAI 兼容 JSON），此时状态码配置不再生效；它与「跳过不可重试状态码」互不影响，命中不可重试规则的错误仍然原样返回，不会被改成 `200` 正文。这类响应在调用日志里按成功记账：状态码显示为黄色 `200`（点开能看到调用方收到的正文与内部失败原因），不计入失败日志与失败率
- **自定义内容返回**：在模型「高级设置」里开启并填写返回内容（例如「好的」）。开启后每次请求都直接返回这段内容，不请求上游，也不需要配置路由。返回内容分「文本 / JSON」两页：文本页按对话结构返回，流式请求按 SSE、非流式按 OpenAI 兼容 JSON，还可以填写思考内容（留空则不输出思考字段）并模拟流式首字等待、流式速度（每秒字符数）和非流式延迟；JSON 页直接把填写的整段 JSON 原文返回（`200` / `application/json`），无论流式还是非流式都不再套用对话结构，可以用来返回生图等其它类型的响应体（此时流式首字和速度不生效，非流式延迟仍然有效）。开启内容返回会自动关闭错误覆写
- **系统提示词注入**：在模型「高级设置」里开启并填写提示词后，网关会在转发前删除请求里自带的全部系统提示词（OpenAI 对话的 `system` / `developer` 消息、Anthropic 原生的顶层 `system` 字段、Responses API 的 `instructions` 以及 input 里的系统条目），只把配置内容作为唯一的系统提示词放在最前面。适合把模型包装成自带人格设定的专用入口，调用方无法再用自己的系统提示词覆盖；仅对对话类请求生效
- **思考覆写**：在模型「高级设置」里开启后，模型返回的思考内容会替换为填写的内容（例如「正在思考···」），上游真实的思考内容不会发给客户端；留空则完全隐藏思考字段，客户端会一直等到正文开始输出。流式 / 非流式、对话 / 补全 / Responses 端点都支持，正文、工具调用和用量统计不受影响。自定义内容返回优先级最高，开启后思考覆写不生效
- **路由可选**：自定义模型不要求必须配置路由。没有路由时按「高级设置」里的自定义内容返回 / 始终返回错误处理；两者都没有配置时，调用会正常返回「没有可用渠道」的错误
- **可视化 / JSON**：路由配置可在可视化编辑器与 JSON 之间双向切换，JSON 可以直接复制粘贴，方便备份和复用
- **能力参数**：工具调用、思考、图片输入支持「不设置 / 支持 / 不支持」三态；选择「不支持」时可以决定检测到相关内容时直接报错（400），还是自动移除后继续转发；同样支持可视化 / JSON 双向编辑

「模型管理」列表会直接标出每个模型的实际状态：**可用**、**不可用**、**已禁用**、**渠道已禁用**、**渠道模型不存在**、**始终返回内容**、**始终错误 (状态码)**、**始终返回正文**。自定义模型只要还有一条路由可用就整体可用，不可用的条目会在路由编辑器里单独标出。点击列表中的任意一行可以打开详情抽屉，查看能力参数、路由和近 24 小时统计。模型允许先保存、之后再补渠道或上游模型名，保存时不会因为引用暂时不存在而被拒绝；启停等部分更新也不会清空已有的路由、参数和描述。

模型编辑弹窗里可以设置**超时时间**（默认 300 秒）：非流式请求限制整次调用；流式请求限制「两段真实输出之间的最大空档」，首字到达后每来一段正文 / 思考 / 工具参数就重新计时，心跳和空块不续命，上游吐一半卡住同样会立刻判失败；开启**强制流式请求**后，非流式调用也按这个空档计算，慢上游迟迟不吐字时能更快失败并切到下一条路由。自定义模型开启**亲和**后，上次成功的路由会在下次请求时排在首位，并从它开始继续顺延其余路由；调用日志上游模型列里，上游模型徽章右上角的橙色星标表示本次命中了亲和。失败的路由会进入**冷却**，冷却时长按模型当前的配置实时计算，修改冷却时长的配置对已经在冷却中的路由立即生效。清除冷却有三种方式：模型列表右上角的「清除冷却」清空全部运行时冷却与亲和；多选模型后点工具栏的「清除冷却」只清理选中模型涉及的路由和该模型的亲和；管理接口也支持按模型（`?model_id=`）或按渠道（`?channel_id=`）清除，按渠道清除时会同时清掉该渠道下 Key 的冷却与 Key 亲和，以及指向该渠道的模型亲和。冷却和亲和都只存在当前进程内存中，重启后自然清空。

### 提供商（Provider）

提供商用于给模型归类、显示图标，并在模型广场按厂商筛选。首次启动会自动写入这些内置提供商：

| 提供商 | 自动匹配关键词 |
| --- | --- |
| 智谱 | `glm` |
| DeepSeek | `deepseek` |
| xAI | `grok` |
| OpenAI | `gpt` |
| 阶跃星辰 | `step` |
| 字节跳动 | `doubao` |
| 小米 | `mimo` |
| MiniMax | `minimax` |
| Google | `gemini` |
| Anthropic | `claude` |
| 月之暗面 | `kimi` |
| 阿里巴巴 | `qwen` |

每个内置提供商默认只保留一个主关键词，避免和名称相近的模型互相抢归属；需要额外关键词时可在「提供商管理 → 编辑」里自行添加。提供商 ID（如 `google`、`anthropic`）是内部稳定标识，模型通过 `provider_id` 引用它，创建后不可修改；新建提供商时不用手填 ID，由程序按名称自动生成，改名只影响展示，不影响已有模型的归属。

添加模型时会按上游模型名自动归属提供商，并自动使用该提供商的图标；也可以在「模型管理 → 编辑」里手动修改，或用多选工具栏「批量设置提供商」统一调整。自定义提供商支持选择内置图标、填写 emoji 或图片直链，以及自定义匹配关键词。删除内置提供商后，可在「提供商管理 → 恢复内置提供商」里勾选需要找回的项，恢复后失去归属的模型会自动重新匹配。

模型广场只展示有可用模型的提供商筛选项；没有模型的提供商会自动隐藏。

### 能力参数

每个模型都可以单独声明能力，所有项都支持三态：

| 参数 | 可选值 |
| --- | --- |
| 上下文长度 | 数字 / 留空（不声明） |
| 最大输出 | 数字 / 留空（不声明） |
| 工具调用 | 不设置 / 支持 / 不支持 |
| 思考（Reasoning） | 不设置 / 支持 / 不支持 |
| 图片输入（Vision） | 不设置 / 支持 / 不支持 |

「工具调用」「思考」「图片输入」选择**不支持**时，会额外出现「不支持时报错（400）」开关：

- **开启报错**：请求里检测到对应内容时直接返回 400，错误文案为「模型「xxx」不支持思考」「模型「xxx」不支持工具调用」「模型「xxx」不支持图片输入」。工具调用会检查 `tools` / `functions` 定义以及消息里的工具调用和工具结果；思考会检查 `reasoning_effort`、`thinking`、`enable_thinking` 等思考参数，以及历史消息里的 `reasoning_content` / `thinking` 内容块（可用于防止思考注入）；图片会检查消息内容里的 `image_url` / `input_image` / `image` 内容块。
- **关闭报错**：自动从请求上下文里移除这些内容（工具定义、工具调用与工具结果消息、思考参数与思考历史、图片内容块）后继续转发；只有图片的消息会留下一条占位文本。

选择**不设置**或**支持**时，网关不会做任何能力相关的校验或改写（模型名替换和协议转换仍会正常进行）。上下文长度和最大输出仍然只用于模型广场和模型列表的展示。

能力参数支持可视化与 JSON 两种编辑方式，JSON 可以直接复制粘贴，方便备份和复用。JSON 示例：

```json
{
  "context_length": 128000,
  "max_output": 8192,
  "tool_calling": false,
  "tool_calling_error": true,
  "thinking": false,
  "thinking_error": false,
  "vision": true
}
```

## 使用方式

网关完全兼容 OpenAI 协议，任何 OpenAI SDK 只要换掉 `base_url` 和 `api_key` 即可。

### curl

```bash
curl http://127.0.0.1:6700/v1/chat/completions \
  -H "Authorization: Bearer sk-ldm-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "LDM",
    "messages": [{"role": "user", "content": "你好"}],
    "stream": true
  }'
```

### Python（openai SDK）

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:6700/v1",
    api_key="sk-ldm-xxxxxxxx",
)

resp = client.chat.completions.create(
    model="LDM",
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)
```

### Node.js

```js
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://127.0.0.1:6700/v1",
  apiKey: "sk-ldm-xxxxxxxx",
});

const stream = await client.chat.completions.create({
  model: "LDM",
  messages: [{ role: "user", content: "你好" }],
  stream: true,
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content || "");
}
```

### 可用端点

| 端点 | 说明 |
| --- | --- |
| `GET /v1/models` | 列出当前密钥可调用的模型 |
| `POST /v1/chat/completions` | 对话补全，支持流式 |
| `POST /v1/completions`、`/v1/embeddings`、`/v1/images/generations` 等 | 模型调用端点，原样转发到上游（OpenAI 兼容渠道） |
| `POST /v1/messages` | Anthropic 原生协议入口 |

API 密钥只能调用模型相关端点。完整白名单：`chat/completions`、`completions`、
`messages`、`responses`、`responses/compact`、`embeddings`、`images/generations`、
`images/edits`、`edits`、`audio/transcriptions`、`audio/translations`、`audio/speech`、
`rerank`、`moderations`、`engines/{model}/embeddings`。
`/v1/files`、`/v1/fine-tunes`、`/v1/batches`、`/v1/vector_stores` 等账号级接口
会在网关层直接返回 `404`，不会转发到上游。

除对话模型外，图片生成/编辑、语音转写/翻译/合成、嵌入、重排、内容审核等模型调用同样可用：

- `multipart/form-data` 请求（`/v1/images/edits`、`/v1/audio/transcriptions`、`/v1/audio/translations`）
  会从表单里读取 `model`，按路由改写成渠道的上游模型名后重建表单转发，图片/音频文件与其它字段原样保留。
- 转发时使用真实的 `Content-Type`（multipart 会生成新的 boundary），调用方的 `Accept` 也会保留；
  `/v1/audio/speech` 等二进制响应和转写文本响应都会原样返回。
- 音频转写/翻译、语音合成、内容审核省略 `model` 时，分别按 `whisper-1`、`tts-1`、
  `text-moderation-stable` 路由；需要在模型管理里配置同名模型。

密钥不存在、已禁用或已过期时统一返回 `401 invalid_api_key`（对外不区分具体原因）；只有额度用尽才返回
`403 insufficient_quota`，并在错误信息里带上已用 / 总额度。

模型在模型管理里被禁用、或者根本没有这个模型 ID 时，调用一律返回 `404` 和「模型「xxx」不存在」——
对外不区分「不存在」和「已禁用」，调用方无法通过调用探测出某个模型只是被停用了。

令牌可以设置来源 IP 白名单（令牌管理 → 编辑密钥 → IP 限制）。留空表示不限制；支持单个 IPv4 / IPv6 地址、
CIDR 网段（如 `10.0.0.0/8`）和 IPv4 尾部通配（如 `192.168.1.*`）。不在白名单内的请求返回
`403 ip_not_allowed`。只有直连方是本机或内网（同机反向代理、Docker 网关）时才会读取
`X-Forwarded-For` 的最后一跳，公网直连时忽略该请求头，避免伪造代理头绕过白名单。

### 看板时间范围

看板右上角和调用日志用同一套选法：先在下拉里选「今日 / 昨日 / 近 7 天 / 近 30 天 / 全部时间 / 自定义」，后面两个输入框显示这一段的具体起止时间；直接改时间就会自动落到「自定义」。预设都是**自然周期**：今日从北京时间 0 点开始，昨日是整天，近 7 天含今天共 7 天。时间框可以留空：两个都空就是「全部时间」，只填结束就是从最早一条记录算到那一刻。

趋势图在一天以内的区间按小时聚合，超过一天按自然日聚合。

请求量、Token、成功率与平均速度会与**上一周期的同期区间**对比（今日较昨日同期、近 7 天较前 7 天、自定义较紧邻的等长区间），环比数字显示在卡片下方。所有时间划分与图表标签固定使用北京时间（UTC+8），服务器运行在其它时区也不影响统计口径。

### 看板按模型看趋势

「调用趋势」下方有一排图例，既是曲线说明也是视图开关，从左到右依次是**各模型**、**总计**和每个模型：

- **各模型**：每个模型一条总请求数曲线（下面还有一条总失败数红线），一眼看清谁调用得最多；
- **总计**：请求数 / 成功数 / 失败数三条曲线，看整体走势；
- **某个模型**：该模型自己的请求数 / 成功数 / 失败数三条曲线，同时统计卡、成功率、Token、平均速度都换成这个模型的数字，「模型调用分布」环形图里其余模型变灰。

点模型时只重画受影响的区域，页面不会整块刷新。图表右上角还能在「请求数 / Token」之间切换，Token 维度看输入 / 输出构成。

坐标轴上限会贴着数据选，不会出现「数据最高 66、上限却到 100」这种上面一大截全空的情况。

> 请求数、失败数按模型拆分从很早就开始记录，历史数据一样能按模型看；**Token 和平均速度是升级后才开始按模型记录的**，翻老区间时这两个指标会显示为空。

### 模型调用分布切换口径

「模型调用分布」环形图右上角有一个**「请求数 / Token」**开关，可以自己切：

- **请求数**：按各模型的调用次数看占比，中心是总调用次数；
- **Token**：按各模型的 Token 消耗看占比，中心是总 Token，副标题也会写明当前口径。

这个开关和调用趋势右上角的维度开关各管各的，互不影响。切到 Token 时环形图会按 Token 消耗从大到小排，但**颜色跟着模型走**——同一个模型在环形图和趋势图例里永远是同一个颜色。

> Token 口径下用的是「按 Token 消耗排」的模型列表：调用次数不多、单次却特别长的模型在「调用次数前 12」里排不进来，切到 Token 时不会漏掉它。老数据没有按模型记过 Token 时，副标题会注明「历史数据未按模型记录 Token」。

### 看板数字单位

数据看板右上角的单位下拉可以切换统计数字的显示方式：「英文单位」按 K / M / B 缩写，「中文单位」按万 / 亿缩写，「无单位」显示完整数字。看板卡片、趋势图、分布图和排行榜会一起切换，选择记在浏览器本地。

### 模型测试

「模型管理」里每个模型都有测试按钮，会发起一次真实的最小调用，并在提示里给出：
耗时、实际落到的渠道与上游模型、Token 用量，以及上游返回的正文。失败时同样会展示
上游返回的错误内容。测试调用与正常调用一样计入日志和统计。提示条右上角的复制按钮
可以把这条提示的标题和正文一次复制走，报错内容长的时候不用再手动选中。

### 备份导出

「系统设置 → 备份导出」可以把配置和数据写成一份 JSON，保存到运行网关的设备上。可勾选的范围包括渠道配置、模型配置、提供商、API 密钥、系统设置、调用日志和统计数据，默认全部不勾选。

- 文件写入数据目录下的 `backups/`，文件名形如 `ldmapi-backup-20261020-120000-abc123.json`。
- 支持紧凑、2 空格缩进和 4 空格缩进，默认 2 空格。
- **不会通过浏览器下载**：文件里有明文上游 Key 和 API 密钥，为了不绕过渠道密钥掩码，接口只返回服务器上的路径，不把内容发给浏览器。网关部署在远程服务器时，请通过 SSH / SFTP 到该路径取回。
- 导出期间会暂停所有数据写入，直到文件写完，保证备份里的渠道、模型、日志等内容来自同一时刻。
- Linux / macOS 下文件权限为 `0600`；备份包含敏感信息，请妥善保管。

需要整库迁移时，也可以在停止服务后直接复制 `data/ldmapi.db`。

### 修改自定义模型的 ID

自定义模型的 ID 可以随时改。历史日志保留改名时使用的旧 ID，统计则从改名时刻起累计到新 ID 上。

渠道模型的 ID 由「渠道 ID / 上游模型名」推导而来，不能修改——需要改名时请修改渠道里的模型名。

### 深度思考的展示

模型如果输出了思考内容（DeepSeek-R1 这类推理模型会通过 `reasoning_content` 字段返回），
「在线聊天」会把它放在正文上方的**可折叠块**里：思考过程中默认展开、实时滚动，一旦开始输出正式回答
就自动收起，只保留「深度思考 N 字」的标题，需要时点开还能看。

思考内容不会写进对话历史，因此不会在下一轮被当作上下文重新发回给模型。

### Markdown 渲染

模型回复里的 Markdown 会直接渲染成排版好的内容：标题、列表、表格、代码块（右上角带复制按钮）、引用、分割线、链接、图片，以及 LaTeX 公式（`$...$` 行内、`$$...$$` 独立成块，用 KaTeX 排版）都支持，流式输出时边生成边渲染。

- 行内公式写在 `$...$` 里（紧贴中文也能认出来），独立公式用 `$$...$$`；同一段文字里如果出现两个美元金额（如 `$5 到 $10`），有可能被当成行内公式，这种句子建议写成「5 美元」。
- 每条回复下方的操作栏有一个 Markdown 切换图标按钮（渲染着时是代码图标，点开看源码；在原文状态时是眼睛图标，点一下恢复渲染），单条切换看源码还是看效果。用户自己发的消息同样会渲染。
- 解析器（marked）、公式扩展（marked-katex-extension）、公式排版（KaTeX）与消毒器（DOMPurify）都打包在 `web/assets` 里随二进制分发，不依赖 CDN，内网与离线环境照常可用。模型输出按不可信内容处理：走 DOMPurify 的 HTML / MathML / SVG 白名单，`javascript:` 链接、`on*` 内联事件和 `<script>` 会被清掉，KaTeX 关掉 trust（`\href` 之类的命令不会被放行），外链一律新窗口打开。

### 图片、附件与自定义请求体

在线聊天支持三种补充输入：

- **图片**：点输入框左侧的图片按钮选择，也可以直接粘贴或拖入。图片会先在浏览器里压缩到最长边 1600px，再以多模态 `image_url` 内容块发给模型。
- **附件**：点回形针按钮选择。消息里只显示附件卡片，点击后在右侧抽屉查看：文本类文件和图片可直接预览，PDF 会调用浏览器内置阅读器显示，Word、压缩包等二进制文件提示不支持在线预览并提供下载。文本类文件（txt / md / json / csv / 代码等）会内联成文本发给模型；PDF、Word 等二进制文件以 `file` 内容块发送，Anthropic / Gemini 渠道会自动转换成各自的 document / inlineData 格式。
- **自定义请求体**：打开左侧设置栏最上方的「自定义请求体」开关，模型、流式与采样参数会隐藏，改为显示当前请求的 JSON。发送时以编辑器里的 JSON 原文为准，可以直接添加 `tools`、`response_format` 等字段；输入框里的文字会追加成一条 user 消息。发送后以 JSON 里的 `messages` 作为后续对话历史。

采样参数包括温度、Top P、频率惩罚、存在惩罚、最大 Token 与种子，每一项都有独立开关，只有开启且填了值的参数才会发给上游（0 也会照常发送）。设置保存在浏览器本地，下次打开仍在；点参数标题右侧的「重置」可以恢复全部默认值与默认开关状态。

### 临时测试（不配置渠道和模型）

在线聊天的模型下拉里有一个「临时测试（直连上游）」选项。选中后填写上游 API 地址和 Key，点「获取模型」可以从上游拉取模型列表（也可以直接手填模型 ID），然后像平常一样发消息测试。

- 不需要先配置渠道或模型，请求直接发往填写的上游地址，只支持 OpenAI 兼容的 `/chat/completions` 协议。
- 临时测试的调用**不写入调用日志和统计**；地址和模型保存在浏览器本地，Key 只放在 `sessionStorage`，关闭标签页后清除。
- API 地址可以填裸域名（自动补 `/v1`）、带版本段的基础地址（`/v1`、`/api/v3`、`/v1beta` 等）或完整的 `/chat/completions` 端点。
- 流式 / 非流式、采样参数与自定义请求体都可以正常使用；上游返回的错误会原样显示在对话里。

### 工具调用测试

左侧设置栏「生成」里有一个「工具调用」开关。开启后，每次请求都会带上一个获取当前时间的 `get_current_time` 工具（可传 `timezone`，留空使用浏览器本地时区）：

- 模型返回工具调用时，浏览器会执行该工具，把结果作为 `tool` 消息回传并自动请求下一轮，最多连续 3 轮，避免模型在工具之间循环。
- 回复气泡会按模型的实际输出顺序显示正文和工具调用卡片：同一轮的多条调用合并在同一张卡片里，标题显示调用次数，内部依次列出每次调用的名称、参数与结果（只有一次调用时也用同样结构），默认展开；气泡下方的统计会显示「工具调用 N 次」。
- 流式、非流式都支持；配合「临时测试」直连上游时，可以绕过渠道与模型配置，直接判断模型本身是否支持工具调用。
- 开关状态保存在浏览器本地。自定义请求体模式下不生效，需要测试时请在 JSON 里自行添加 `tools`。

模型选择框下方的来源 / 路由信息超过一行时会自动省略，点右侧的展开按钮查看完整内容；切换模型后会自动收起。自定义模型尚未配置路由时会显示「未配置」。

左侧设置栏可以点右上角的收起按钮折叠，收起后对话区顶部会显示齿轮按钮和当前模型，点齿轮即可重新展开；窄屏下设置栏改为抽屉。对话卡片会撑满内容区，不会在底部留空。

图片和附件都直接编码进请求体，不经过服务端文件存储，因此单次请求体上限为 64MB。浏览器本地存储空间不足时对话仍可继续，但刷新后可能丢失附件。

对话记录保存在**浏览器本地**（`localStorage`），刷新页面或下次打开都还在；切换模型不会另起一段，只影响之后发出的消息。点「清空对话」会清空整份记录。

切到其它页面不会中断正在生成的回复，回来后会自动接上当前的流；刷新或关闭页面前会把已生成的部分保存下来。调用失败的消息会保留错误信息和重试按钮，错误内容不会进入下一轮上下文。

每条回复的气泡下方会带三组统计，组之间用竖线分隔：

```
输入 11 · 缓存读 8  |  输出 36 · 思考 30 · 27.6 tok/s  |  首字 320ms · 总耗时 2.1s · 总 47
```

- **输入组**：输入 token 总量，以及其中命中提示词缓存的部分（上游没开缓存或没上报时这一项不显示）
- **输出组**：输出 token、思考 token、生成速度——都是和输出相关的指标
- **耗时组**：首字耗时、总耗时，以及这次请求的总 token

缓存命中会从各家的不同字段里归一化：OpenAI 的 `prompt_tokens_details.cached_tokens`、
DeepSeek 的 `prompt_cache_hit_tokens`、Anthropic 的 `cache_read_input_tokens`、
Gemini 的 `cachedContentTokenCount`，最终都以 OpenAI 的字段形式透出。

这些数据在刷新后也会一起恢复。

### 模型选择弹窗的搜索与分组

「模型管理 → 添加模型」、自定义模型的「选择渠道模型」和令牌的「模型权限」共用同一个弹窗，支持按模型名
模糊搜索（渠道 ID、上游模型名和提供商名称都能匹配），没有命中的分组会自动隐藏。弹窗可以在「按渠道分组」
和「按提供商分组」之间切换，两种视图分别记住折叠状态；点分组标题可以折叠/展开，也可以一键
「展开全部 / 折叠全部」。

搜索状态下「全选可添加」只会选中当前可见的条目，不会误选被过滤掉的内容；折叠只是显示状态，不影响分组
全选与已选统计。令牌的模型权限只列出「模型管理」里已启用的模型，没有渠道的自定义模型归到
「自定义模型」分组；勾选结果会合并到令牌编辑弹窗里手动填写的模型名中，下方的模型徽章实时预览，点击模型名即可复制。

令牌的模型权限也可以直接手填模型名，每行一个或用逗号、分号分隔，支持 `*` 通配符：`*` 匹配任意长度（包括空）
且能跨过 `/`，例如 `*deepseek*` 匹配所有名字里带 deepseek 的模型（包括带渠道前缀的），`deepseek*` 只匹配
以 deepseek 开头的模型，单独一个 `*` 表示全部模型。留空同样表示可以使用全部模型。

### 输出速度与思考长度

「调用日志」一行一条记录，列宽按内容撑开：窗口放不下时整张表左右滚动，不会把内容压成多层换行；「状态」列固定在右侧，横向滚动时成败始终可见。表头与内容一样左对齐、用正文色显示，只有数值列的次要指标跟在数值下面另起一行：

| 列 | 内容 |
| --- | --- |
| 请求模型 | 客户端请求的模型 ID 徽章，后面跟流式 / 重试标签 |
| 渠道 | 渠道 ID（名称）徽章 + 多 Key 渠道本次使用的 Key 徽章，命中 Key 亲和时徽章右上角有橙色星标 |
| 上游模型 | 本次实际调用的上游模型名徽章，命中模型亲和时右上角有橙色星标；上游响应里回显的模型名和它不同时，徽章内右侧带一枚路由图标（见下） |
| **输入** | 输入 token 总量；下面一行灰字是命中提示词缓存的部分（`缓存读 N`，没命中则不显示） |
| **输出** | 输出 token 总量；下面一行灰字是思考 token（`思考 N`，上游未上报时退回显示字符数） |
| **速度** | 输出速度（t/s），按生成耗时计算；只按流式请求了上游才有值（上游直接回完整 JSON、非生成类请求显示 `—`） |
| **总计** | 本次请求的总 token |
| **耗时** | 总耗时（含全部重试）；下面一行灰字是首字耗时 |

「首字耗时」量的是**第一段真实内容**到达的时间：只看响应头、只收到只带 `role` 的空块或心跳都不算，所以它比「响应头到达时间」更贴近调用方看到第一个字的时间。它只取最终成功的那一次尝试，前面失败路由花掉的时间体现在总耗时里（点开重试历史能看到每次尝试各自的耗时）；上游忽略流式、直接返回完整 JSON 的普通非流式请求没有首字耗时。

日志工具栏的「单位」开关（默认开启）会把 Token 数缩写为 K / M / B，鼠标悬停仍能看到精确值；关掉后恢复完整数字。
状态筛选除了「成功 / 失败」，还可以选「有重试」：只显示发生过重试的请求，不区分最终成功还是失败。

失败记录的状态码徽章可以点击查看「错误信息」：上方概要列出请求模型、渠道模型、渠道和状态码，下面分成两个独立区块——「错误详情」是调用方实际收到的内容（上游错误会原样展示），「内部原因」只用于后台排查，可能包含渠道、上游地址等细节。

请求模型、渠道、上游模型各占一列：渠道列是渠道 ID（名称）徽章，后面跟本次最终使用的 Key；上游模型列是实际调用的上游模型名，命中模型亲和时徽章右上角有橙色星标。有些上游会把请求的模型名解析成别的名字回显（别名指向具体版本、自动降级到便宜模型等），这时上游模型徽章内右侧会带一枚路由图标：鼠标移上去（手机上点一下徽章）弹出气泡卡片，「请求模型 / 响应模型」左右两行，各是一枚点一下就能复制的徽章；桌面上点徽章本身仍是直接复制模型名。上游原样回显模型名或完全不回显时徽章保持原样。直接调用渠道模型时请求模型是 `A/a`、上游模型是 `a`，星标仍在上游模型上。多 Key 渠道的 Key 以紧凑彩色徽章显示 `#序号`，有备注时跟在序号后面（例如 `#2 备用账号`），没有备注时显示 `#3（无备注）`；命中 Key 亲和时徽章右上角有橙色星标。带重试的日志会显示「重试 N」徽章，点开后先看到按「渠道 + 上游模型」分行的重试信息（同一渠道的不同上游模型不会合并）；如果某个渠道内换过多个 Key，再点该行的「Key 重试」继续下钻，查看每次 Key 尝试的状态码、耗时和错误，Key 同样以 `#序号 + 备注` 显示，命中亲和的那次尝试也会带星标。

速度的分母用的是**生成耗时**而不是总耗时——首字之前的排队和建连时间不应该算进生成速度。这里的生成耗时是
转发层实测的「首块内容 → 末块内容」间隔，不是「总耗时 − 首字耗时」：上游把整段响应一次性吐完时（缓存命中、
上游侧做了缓冲、自定义内容返回没有配置流式速度），两者只差几毫秒，用它们当分母会算出几万 t/s 这种没有意义
的数值。生成窗口小于 50 毫秒的记录一律不计速度，也不计入数据看板的「平均速度」。

没量到生成窗口的记录同样不计速度，也不会退回用「总耗时 − 首字耗时」估算——那段时间里除了生成，还混着首字
之后的收尾（usage 块、`[DONE]`、上游发完不急着断连接），拿它当分母会把「内容一把梭 + 连接空转」算成上千 t/s。
上游一次性写完、整段内容在同一毫秒内写完，都属于这种情况，速度显示 `—`。

请求模型列的「流式」徽章只看**客户端的请求**：请求体里写了 `stream: true` 就标，和上游最后回的是 SSE 还是
完整 JSON 无关。

输出速度只看**是不是按流式请求了上游**：上游一块一块吐出来的就算，和写给客户端的形态无关。所以两边会对不上，
而且各有各的道理：

- 调用方要非流式、模型开了「强制流式请求」——徽章不标「流式」，但上游是按 `stream: true` 请求的，速度照常计算；
- 调用方要流式、上游却直接回了完整 JSON——徽章标「流式」，但上游没有生成窗口，速度显示 `—`。

真正一次性的非流式请求（上游也回完整 JSON）没有生成窗口，首字和速度都不显示，只保留总耗时。

思考用量优先用上游单独上报的数值（OpenAI 的 `completion_tokens_details.reasoning_tokens`、
Gemini 的 `thoughtsTokenCount`）；上游没上报时退回显示思考内容的字符数（`思考 N 字`）。
Anthropic 把思考算在 `output_tokens` 里，所以那一栏会显示字符数。

缓存命中同样从各家不同字段归一化：OpenAI 的 `prompt_tokens_details.cached_tokens`、
DeepSeek 的 `prompt_cache_hit_tokens`、Anthropic 的 `cache_read_input_tokens`、
Gemini 的 `cachedContentTokenCount`。

## 常见问题

**Q：为什么配好了渠道，调用还是提示模型不存在？**
模型需要在「模型管理」里手动添加一次。这是刻意设计的，避免渠道里填的上游模型名被意外暴露出去。

**Q：一个渠道下能填多少个模型？**
不限制。只有被添加进「模型管理」的那些才会对外开放，其余只是候选。

**Q：上游不是 OpenAI 协议怎么办？**
渠道类型选 Anthropic 或 Gemini，网关会做协议转换。其它协议可以先看看是否兼容 OpenAI（绝大多数国内服务商都兼容）。

**Q：自定义模型的路由是负载均衡还是故障转移？**
默认是**顺序故障转移**——永远优先用第一个，只有它挂了才往下走。想分摊流量就把策略改成「轮询均衡」。

**Q：删除了渠道，模型管理里的模型为什么还在？**
删除渠道默认只删除渠道本身，模型配置会保留并标记为「渠道模型不存在」或「渠道已禁用」，方便之后重建同名渠道或调整路由。需要一起清理时，可以在删除确认框里选择「删除并移除模型」，也可以在模型管理里手动删除。

**Q：调用返回「模型暂不可用」，但日志里有更详细的原因？**
对外错误只说明模型不可用，不会暴露渠道 ID、渠道状态或上游地址；具体是哪个渠道、什么原因只记录在调用日志里。上游自己返回的错误会原样透传。

**Q：数据存在哪里？怎么备份？**
`data/ldmapi.db`（bbolt 单文件数据库）。停止服务后直接复制这个文件即可；也可以在「系统设置 → 备份导出」里勾选需要的内容，导出一份 JSON 到服务器的 `data/backups/` 目录。备份文件包含明文上游 Key 和 API 密钥，因此只写入服务器本地、不通过浏览器下载，请妥善保管。

**Q：忘记管理密码了？**
用 `-password 新密码` 启动一次即可重置。

需要 Go 1.24 或更高版本。

```bash
git clone <repo> && cd ldmapi
go build -o ldmapi .
```

交叉编译：

```bash
# Windows
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o dist/ldmapi-windows-amd64.exe .

# Linux
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o dist/ldmapi-linux-amd64 .
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags "-s -w" -o dist/ldmapi-linux-arm64 .
```

Windows 产物的图标和版本信息来自 `assets/ldmapi.ico`，由 `go-winres` 生成 `rsrc_windows_*.syso`，`go build` 会自动链接。仓库里已包含生成好的 syso；更新图标后重新生成：

```bash
go install github.com/tc-hib/go-winres@latest
go-winres simply --arch amd64,arm64 --icon assets/ldmapi.ico \
  --product-name "懒大猫 API" --file-description "懒大猫 API - 模型聚合网关" \
  --product-version 1.27.4 --file-version 1.27.4 --original-filename ldmapi.exe
```

修改前端时不必重新编译，让程序直接从磁盘读取前端资源即可：

```bash
LDMAPI_DEV=web go run . -port 3000
```

## 安全提示

- 默认密码是 `landamao`，**首次登录后请立刻修改**。登录接口按客户端 IP 限制为每 10 分钟最多 10 次尝试，密码错误时响应会延迟 2 秒。
- 网关默认只监听 `127.0.0.1`。如果需要局域网或公网访问，显式传 `-host 0.0.0.0`，并建议放在 Nginx / Caddy 之后，或加防火墙规则。
- 管理接口只接受登录会话 Cookie，API 密钥只能调用模型相关端点，无法访问管理接口或文件、微调、批处理等账号级上游接口。
- 管理端的写请求会校验 `Origin` / `Referer` / `Sec-Fetch-Site`，只接受同源页面发起，跨站页面无法借登录态提交操作；`/api` 不返回 CORS 头，只有对外的 `/v1` 接口允许浏览器跨域调用。
- 修改管理密码会立即让此前签发的所有登录会话失效。
- 上游渠道的 API Key 以明文保存在本地数据文件中，请确保该文件权限正确（默认 `0600`）；保存渠道的接口响应只返回脱敏后的密钥。
- 对外错误只返回模型级结论，不包含渠道 ID、渠道状态与上游地址；上游原始错误会原样透传，详细原因记录在调用日志中。
