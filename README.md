# 🐱 懒大猫 API

一个 **单文件、开箱即用** 的模型聚合网关。把所有上游服务商的模型收拢到一个地址、一个密钥之下，
对外提供完全兼容 OpenAI 协议的接口。

- **一个可执行文件**：前端资源编译进二进制，不需要 Node、不需要数据库、不需要配置文件。
- **一个数据文件**：所有配置、密钥、日志都写进同目录下的 `data/ldmapi.db`。
- **跨平台**：Windows / Linux / macOS 均有预编译产物。

```
                     ┌──────────────┐
   OpenAI SDK ──┐    │              │   ┌── 渠道 A（OpenAI 兼容）
   curl ────────┼──▶│  懒大猫 API   │──▶├── 渠道 B（Anthropic）
   任意客户端  ──┘    │              │   └── 渠道 C（Google Gemini）
   一个密钥           └──────────────┘      自动协议转换 / 失败切换
```

## 核心概念

### 渠道（Channel）

一个上游服务商。渠道 ID 唯一，**不能包含 `/`**，它会成为模型名的前缀。

在「渠道管理」里填的是**上游真实的模型名**（`a`、`b`、`c`），这里不做任何改写。
只有接入到「模型管理」之后，每个模型才会获得一个带渠道前缀的 ID。

```
渠道管理里填写：
  A:  a, b, c
  B:  a, b, d

模型管理里出现：
  A/a、A/b、A/c、B/a、B/b、B/d
```

添加渠道时**接口地址是必填的**，并且必须带上 `https://` 或 `http://`。网关不会在地址留空时替你
回退到官方 API——填错或漏填会导致请求静默打到错误的地方，这类问题很难排查，所以这里直接拒绝保存。

填好地址和 API Key 后，点「获取模型列表」就能直接拉取该服务商支持的模型，**不需要先保存渠道**；
拉取后可以在弹窗里勾选要加入或保留的模型，手工填写但上游未返回的模型会单独列出，模型列表本身也可以留空，先把渠道建好、之后再回来补。

一个渠道可以配置**多个 API Key**，但多 Key 模式默认关闭：关闭时只显示一个 Key 输入框和备注，
不显示「添加 Key」和「Key 调度」。在 API Key 右侧打开「多 Key 模式」后，才会出现多行 Key 表格：
左边「密钥」占 60% 宽度，右边「备注」占 40% 宽度；点「添加 Key」增加一行，点行尾的删除按钮移除整行。
旧数据只有一个 Key 的同样按关闭处理；已经配置多个 Key 的旧数据保持开启，不会丢配置。

已保存的 Key 以掩码显示。**修改备注时请求里只带该行的下标和新备注，不会重新提交密钥**；只有主动改写密钥列
才会替换 Key。清空某一行的密钥或删除整行即删除对应的 Key。关闭多 Key 模式只影响调度：请求始终只用第一个 Key，
其余 Key 保留在配置里不删除，重新打开开关即可继续使用；只有一个 Key 时也可以填写备注。
密钥和备注的前后空格都会被去掉。

多 Key 的调度策略：

- **顺序**：按配置顺序尝试；未开启亲和时始终从第一个可用 Key 开始。
- **随机**：每次请求把可用 Key 完整打乱后依次尝试。
- **Key 亲和**：上次成功的 Key 优先。顺序模式从它在配置里的位置开始顺延，其余 Key 保持原顺序；随机模式先试它，其余 Key 打乱后顺延。命中时调用日志的 Key 徽章右上角会显示橙色星标。
- **失败冷却**：Key 失败后在设定时间内跳过（0 = 不冷却）。可在渠道的「Key 调度」里用状态码规则调整（支持 `400-430` 区间，输入框右上角可一键填入常用模板，模板为 401 / 403 / 408 / 429 / 5xx；留空表示任何状态码都不冷却 Key，未配置过的旧数据也按留空处理）。
- **全部冷却时重置**：所有 Key 都在冷却中时，自动清空该渠道的 Key 冷却，再按调度规则重试一遍（默认关闭）。

请求渠道模型时，先选定渠道模型，再按上述策略选择 Key；请求自定义模型时，先按模型路由选出渠道模型，
再在命中的渠道内选择 Key。某个 Key 返回的状态码命中渠道的「触发 Key 冷却的状态码」时，
会先在同渠道内换 Key；不在列表里的状态码仍会继续路由，但不冷却 Key。只有这条渠道的所有 Key
都失败后才继续下一条模型路由。渠道管理里的「测试连通性」会逐个尝试 Key，
任意一个可用即视为渠道可用。Multi-Key 的冷却和亲和状态只保存在当前进程内存中，重启后自然清空。

支持的渠道类型：

| 类型 | 适用服务 |
| --- | --- |
| **OpenAI 兼容** | OpenAI、DeepSeek、通义千问、月之暗面、智谱、Ollama、vLLM、OneAPI 等一切兼容 `/v1/chat/completions` 的服务 |
| **Anthropic** | Claude 官方 API（网关自动完成 OpenAI ⇄ Anthropic 双向协议转换） |
| **Google Gemini** | Google AI Studio / Gemini API（自动完成 OpenAI ⇄ Gemini 转换） |

接口地址默认会自动补全 `/v1`。如果服务商的版本前缀不是 `/v1`（例如火山方舟是 `/api/v3`），
把地址填到版本前缀（`https://ark.cn-beijing.volces.com/api/v3`），并关闭渠道编辑里的
「自动补全 /v1」；关闭后网关会按填写的地址原样拼接。

从渠道里移除模型名或删除渠道时，**不会自动改动「模型管理」里的配置**。网关会先列出仍然引用这些模型的渠道模型和自定义路由，由你选择「保留引用」或「一并移除」：删除渠道时可以只删渠道，模型配置保留并显示为不可用；也可以选择一起清理。这样可以避免编辑渠道时误删已经编排好的路由。选择保留的残留路由不会继续转发——渠道模型列表里已经没有这个模型名时，解析阶段会直接跳过它。

### 模型（Model）

**模型设置默认是空的**——即使已经配好了渠道，也必须在这里手动添加，模型才会对外开放。
这样做的好处是：渠道里可以放心地填几十个上游模型名，但只有你真正想开放的那几个会被调用到。

模型分两类：

| 类型 | 说明 |
| --- | --- |
| **渠道模型** | 直接暴露某个渠道下的某个上游模型，ID 形如 `A/a`。 |
| **自定义模型** | 自己起一个 ID（例如 `LDM`），按顺序路由到多个渠道模型。第一个失败（超时 / 限流 / 5xx）时自动切到下一个。 |

```
模型设置列表：
  渠道模型：  A/a、A/c、B/a、B/d
  自定义模型：LDM  →  A/c、B/d
```

调用 `LDM` 时，网关会先打 `A/c`；如果 `A/c` 挂了，请求会自动落到 `B/d`，调用方无感知。

自定义模型还支持：

- **路由策略**：顺序优先 / 轮询均衡 / 随机
- **路由分组**：相邻目标可以「合并」成组，组内每次按权重随机排序后依次尝试（权重越高越可能靠前，权重全部相等时等概率）
- **模型级超时**：每个模型单独设置超时（默认 300 秒）。非流式限制整次请求；流式只限制首字等待，首块数据到达后不再限时
- **模型亲和与失败冷却**：开启亲和后从上次成功的路由位置开始顺延；失败的路由进入冷却，冷却期间自动跳过
- **不可重试状态码**：在模型「高级设置」里配置（支持 `400-430` 区间，输入框右上角可一键填入模板）。命中后直接返回上游错误，不再尝试其它路由，也不记录 Key / 路由冷却；默认留空，表示所有状态码都可重试（未配置过的旧数据也按留空处理），模板 `400-428,430-499`（4xx 中除 429 外都不可重试）。401/403 在还有其它 Key 时仍会先换 Key
- **自定义错误返回**：在模型「高级设置」里填写状态码（400–599）和错误详情，标签旁的「?」可查看完整机制。只开总开关时，请求最终失败（上游报错、超时、无可用路由等）会用配置的错误替代原始错误，成功请求不受影响；再开「始终返回错误」则不请求上游，所有调用都直接返回配置的错误。子开关仅在总开关开启时可用
- **自定义内容返回**：在模型「高级设置」里开启并填写返回内容（例如「好的」）。开启后每次请求都直接返回这段内容，不请求上游，也不需要配置路由；流式请求按 SSE 返回，非流式按 OpenAI 兼容 JSON 返回。还可以填写思考内容（留空则不输出思考字段），并模拟流式首字等待、流式速度（每秒字符数）和非流式延迟。开启内容返回会自动关闭自定义错误返回
- **路由可选**：自定义模型不要求必须配置路由。没有路由时按「高级设置」里的自定义内容返回 / 始终返回错误处理；两者都没有配置时，调用会正常返回「没有可用渠道」的错误
- **可视化 / JSON**：路由配置可在可视化编辑器与 JSON 之间双向切换，JSON 可以直接复制粘贴，方便备份和复用
- **能力参数**：只用于展示，不参与请求校验或改写；同样支持可视化 / JSON 双向编辑

「模型管理」列表会直接标出每个模型的实际状态：**可用**、**不可用**、**已禁用**、**渠道已禁用**、**渠道模型不存在**、**始终返回内容**、**始终错误 (状态码)**。自定义模型只要还有一条路由可用就整体可用，不可用的条目会在路由编辑器里单独标出。点击列表中的任意一行可以打开详情抽屉，查看能力参数、路由和近 24 小时统计。模型允许先保存、之后再补渠道或上游模型名，保存时不会因为引用暂时不存在而被拒绝；启停等部分更新也不会清空已有的路由、参数和描述。

模型编辑弹窗里可以设置**超时时间**（默认 300 秒）：非流式请求限制整次调用，流式请求只限制首字等待，首块数据到达后不再限时。自定义模型开启**亲和**后，上次成功的路由会在下次请求时排在首位，并从它开始继续顺延其余路由；调用日志里的橙色星标表示本次命中了亲和。失败的路由会进入**冷却**，冷却时长按模型当前的配置实时计算，修改冷却时长的配置对已经在冷却中的路由立即生效。清除冷却有三种方式：模型列表右上角的「清除冷却」清空全部运行时冷却；多选模型后点工具栏的「清除冷却」只清理选中模型涉及的路由；管理接口也支持按模型（`?model_id=`）或按渠道（`?channel_id=`）清除。冷却只存在当前进程内存中，重启后自然清空。

### 提供商（Provider）

提供商用于给模型归类、显示图标，并在模型广场按厂商筛选。首次启动会自动写入这些内置提供商：

| 提供商 | 自动匹配关键词 |
| --- | --- |
| 智谱 | `glm`、`zhipu`、`智谱`、`chatglm` |
| DeepSeek | `deepseek`、`深度求索` |
| xAI | `grok`、`xai` |
| OpenAI | `gpt`、`openai`、`chatgpt` |
| 阶跃星辰 | `step`、`stepfun`、`阶跃` |
| 字节跳动 | `doubao`、`豆包`、`bytedance`、`字节` |
| 小米 | `mimo`、`xiaomi`、`小米` |
| MiniMax | `minimax`、`abab` |
| Gemini | `gemin`、`google` |
| Claude | `claude`、`anthropic` |
| 月之暗面 | `kimi`、`moonshot`、`月之暗面` |
| 阿里巴巴 | `qwen`、`qwq`、`tongyi`、`通义`、`千问`、`alibaba` |

添加模型时会按上游模型名自动归属提供商，并自动使用该提供商的图标；也可以在「模型管理 → 编辑」里手动修改，或用多选工具栏「批量设置提供商」统一调整。自定义提供商支持选择内置图标、填写 emoji 或图片直链，以及自定义匹配关键词。删除内置提供商后，可在「提供商管理 → 恢复内置提供商」里勾选需要找回的项，恢复后失去归属的模型会自动重新匹配。

模型广场只展示有可用模型的提供商筛选项；没有模型的提供商会自动隐藏。

### 能力参数

每个模型都可以单独声明能力，所有项都支持三态：

| 参数 | 可选值 |
| --- | --- |
| 上下文长度 | 数字 / 留空（不声明） |
| 最大输出 | 数字 / 留空（不声明） |
| 工具调用 | 留空（不声明） / 支持 / 不支持 |
| 思考（Reasoning） | 留空（不声明） / 支持 / 不支持 |
| 图片输入（Vision） | 留空（不声明） / 支持 / 不支持 |

这些参数**只用于模型广场和模型列表的展示**，网关不会根据它们校验、裁剪或改写请求内容；模型实际支持什么完全由上游决定。全部留空时不会做任何能力相关的处理（模型名替换和协议转换仍会正常进行）。

能力参数支持可视化与 JSON 两种编辑方式，JSON 可以直接复制粘贴，方便备份和复用。JSON 示例：

```json
{
  "context_length": 128000,
  "max_output": 8192,
  "tool_calling": true,
  "thinking": false,
  "vision": true
}
```

## 使用方式

网关完全兼容 OpenAI 协议，任何 OpenAI SDK 只要换掉 `base_url` 和 `api_key` 即可。

### curl

```bash
curl http://127.0.0.1:6700/v1/chat/completions \
  -H "Authorization: Bearer sk-ldm-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "LDM",
    "messages": [{"role": "user", "content": "你好"}],
    "stream": true
  }'
```

### Python（openai SDK）

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:6700/v1",
    api_key="sk-ldm-xxxxxxxx",
)

resp = client.chat.completions.create(
    model="LDM",
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)
```

### Node.js

```js
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://127.0.0.1:6700/v1",
  apiKey: "sk-ldm-xxxxxxxx",
});

const stream = await client.chat.completions.create({
  model: "LDM",
  messages: [{ role: "user", content: "你好" }],
  stream: true,
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content || "");
}
```

### 可用端点

| 端点 | 说明 |
| --- | --- |
| `GET /v1/models` | 列出当前密钥可调用的模型 |
| `POST /v1/chat/completions` | 对话补全，支持流式 |
| `POST /v1/completions`、`/v1/embeddings`、`/v1/images/generations` 等 | 模型调用端点，原样转发到上游（OpenAI 兼容渠道） |
| `POST /v1/messages` | Anthropic 原生协议入口 |

API 密钥只能调用模型相关端点。完整白名单：`chat/completions`、`completions`、
`messages`、`responses`、`responses/compact`、`embeddings`、`images/generations`、
`images/edits`、`edits`、`audio/transcriptions`、`audio/translations`、`audio/speech`、
`rerank`、`moderations`、`engines/{model}/embeddings`。
`/v1/files`、`/v1/fine-tunes`、`/v1/batches`、`/v1/vector_stores` 等账号级接口
会在网关层直接返回 `404`，不会转发到上游。

密钥不存在、已禁用或已过期时统一返回 `401 invalid_api_key`（对外不区分具体原因）；只有额度用尽才返回
`403 insufficient_quota`，并在错误信息里带上已用 / 总额度。

令牌可以设置来源 IP 白名单（令牌管理 → 编辑密钥 → IP 限制）。留空表示不限制；支持单个 IPv4 / IPv6 地址、
CIDR 网段（如 `10.0.0.0/8`）和 IPv4 尾部通配（如 `192.168.1.*`）。不在白名单内的请求返回
`403 ip_not_allowed`。只有直连方是本机或内网（同机反向代理、Docker 网关）时才会读取
`X-Forwarded-For` 的最后一跳，公网直连时忽略该请求头，避免伪造代理头绕过白名单。

## 控制台

| 页面 | 作用 |
| --- | --- |
| **数据看板** | 请求量、Token 消耗、成功率、平均速度（首字 / 总耗时 / 输出速度），模型/渠道/密钥调用分布；支持今日 / 本周 / 本月自然周期与上一周期同期对比，数字单位可在 K/M/B、万/亿与完整数字之间切换 |
| **模型广场** | 以卡片形式浏览所有可用模型，支持按提供商筛选，含能力标签、近 24 小时调用量、近 24 小时与近 200 次成功率，并可按成功率升序 / 降序排序 |
| **在线聊天** | 选一个模型直接对话，用来快速验证接入是否正确；左侧设置栏可调模型与采样参数（每项可单独开关），支持图片/附件、流式输出、自定义请求体与中途停止，调用同样计入日志 |
| **渠道管理** | 增删改上游渠道，测试连通性，一键从上游拉取模型列表 |
| **模型管理** | 批量添加渠道模型、编排自定义模型的路由、设置/批量设置提供商、调整能力参数，并可对任意模型一键测试 |
| **令牌管理** | 创建 API 密钥，设置额度、有效期、模型白名单、来源 IP 白名单 |
| **调用日志** | 每一次请求的完整记录：模型、渠道、耗时、首字时间、Token 用量、输出速度、思考长度、状态码、来源 IP |
| **系统设置** | 站点名称、主题、日志保留策略、运行信息、备份导出、修改管理密码 |

界面默认使用 **浅色 + 粉色** 主题，也可以在左下角切换到深色主题。

### 看板时间范围

看板右上角可以在「今日 / 本周 / 本月」之间切换。三者都是**自然周期**：今日从北京时间 0 点开始，本周从周一 0 点开始，本月从 1 号 0 点开始；趋势图在「今日」下按小时聚合，在「本周 / 本月」下按自然日聚合。

请求量、Token、成功率与平均速度会与**上一周期的同期区间**对比（今日较昨日同期、本周较上周同期、本月较上月同期），环比数字显示在卡片下方。所有时间划分与图表标签固定使用北京时间（UTC+8），服务器运行在其它时区也不影响统计口径。

### 看板数字单位

数据看板右上角的单位下拉可以切换统计数字的显示方式：「英文单位」按 K / M / B 缩写，「中文单位」按万 / 亿缩写，「无单位」显示完整数字。看板卡片、趋势图、分布图和排行榜会一起切换，选择记在浏览器本地。

### 模型测试

「模型管理」里每个模型都有测试按钮，会发起一次真实的最小调用，并在提示里给出：
耗时、实际落到的渠道与上游模型、Token 用量，以及上游返回的正文。失败时同样会展示
上游返回的错误内容。测试调用与正常调用一样计入日志和统计。

### 备份导出

「系统设置 → 备份导出」可以把配置和数据写成一份 JSON，保存到运行网关的设备上。可勾选的范围包括渠道配置、模型配置、提供商、API 密钥、系统设置、调用日志和统计数据，默认全部不勾选。

- 文件写入数据目录下的 `backups/`，文件名形如 `ldmapi-backup-20261020-120000-abc123.json`。
- 支持紧凑、2 空格缩进和 4 空格缩进，默认 2 空格。
- **不会通过浏览器下载**：文件里有明文上游 Key 和 API 密钥，为了不绕过渠道密钥掩码，接口只返回服务器上的路径，不把内容发给浏览器。网关部署在远程服务器时，请通过 SSH / SFTP 到该路径取回。
- 导出期间会暂停所有数据写入，直到文件写完，保证备份里的渠道、模型、日志等内容来自同一时刻。
- Linux / macOS 下文件权限为 `0600`；备份包含敏感信息，请妥善保管。

需要整库迁移时，也可以在停止服务后直接复制 `data/ldmapi.db`。

### 修改自定义模型的 ID

自定义模型的 ID 可以随时改。历史日志保留改名时使用的旧 ID，统计则从改名时刻起累计到新 ID 上。

渠道模型的 ID 由「渠道 ID / 上游模型名」推导而来，不能修改——需要改名时请修改渠道里的模型名。

### 深度思考的展示

模型如果输出了思考内容（DeepSeek-R1 这类推理模型会通过 `reasoning_content` 字段返回），
「在线聊天」会把它放在正文上方的**可折叠块**里：思考过程中默认展开、实时滚动，一旦开始输出正式回答
就自动收起，只保留「深度思考 N 字」的标题，需要时点开还能看。

思考内容不会写进对话历史，因此不会在下一轮被当作上下文重新发回给模型。

### 图片、附件与自定义请求体

在线聊天支持三种补充输入：

- **图片**：点输入框左侧的图片按钮选择，也可以直接粘贴或拖入。图片会先在浏览器里压缩到最长边 1600px，再以多模态 `image_url` 内容块发给模型。
- **附件**：点回形针按钮选择。消息里只显示附件卡片，点击后在右侧抽屉查看：文本类文件和图片可直接预览，PDF 会调用浏览器内置阅读器显示，Word、压缩包等二进制文件提示不支持在线预览并提供下载。文本类文件（txt / md / json / csv / 代码等）会内联成文本发给模型；PDF、Word 等二进制文件以 `file` 内容块发送，Anthropic / Gemini 渠道会自动转换成各自的 document / inlineData 格式。
- **自定义请求体**：打开左侧设置栏最上方的「自定义请求体」开关，模型、流式与采样参数会隐藏，改为显示当前请求的 JSON。发送时以编辑器里的 JSON 原文为准，可以直接添加 `tools`、`response_format` 等字段；输入框里的文字会追加成一条 user 消息。发送后以 JSON 里的 `messages` 作为后续对话历史。

采样参数包括温度、Top P、频率惩罚、存在惩罚、最大 Token 与种子，每一项都有独立开关，只有开启且填了值的参数才会发给上游（0 也会照常发送）。设置保存在浏览器本地，下次打开仍在；点参数标题右侧的「重置」可以恢复全部默认值与默认开关状态。

模型选择框下方的来源 / 路由信息超过一行时会自动省略，点右侧的展开按钮查看完整内容；切换模型后会自动收起。自定义模型尚未配置路由时会显示「未配置」。

左侧设置栏可以点右上角的收起按钮折叠，收起后对话区顶部会显示齿轮按钮和当前模型，点齿轮即可重新展开；窄屏下设置栏改为抽屉。对话卡片会撑满内容区，不会在底部留空。

图片和附件都直接编码进请求体，不经过服务端文件存储，因此单次请求体上限为 64MB。浏览器本地存储空间不足时对话仍可继续，但刷新后可能丢失附件。

对话记录保存在**浏览器本地**（`localStorage`），刷新页面或下次打开都还在；切换模型不会另起一段，只影响之后发出的消息。点「清空对话」会清空整份记录。

切到其它页面不会中断正在生成的回复，回来后会自动接上当前的流；刷新或关闭页面前会把已生成的部分保存下来。调用失败的消息会保留错误信息和重试按钮，错误内容不会进入下一轮上下文。

每条回复的气泡下方会带三组统计，组之间用竖线分隔：

```
输入 11 · 缓存读 8  |  输出 36 · 思考 30 · 27.6 tok/s  |  首字 320ms · 总耗时 2.1s · 总 47
```

- **输入组**：输入 token 总量，以及其中命中提示词缓存的部分（上游没开缓存或没上报时这一项不显示）
- **输出组**：输出 token、思考 token、生成速度——都是和输出相关的指标
- **耗时组**：首字耗时、总耗时，以及这次请求的总 token

缓存命中会从各家的不同字段里归一化：OpenAI 的 `prompt_tokens_details.cached_tokens`、
DeepSeek 的 `prompt_cache_hit_tokens`、Anthropic 的 `cache_read_input_tokens`、
Gemini 的 `cachedContentTokenCount`，最终都以 OpenAI 的字段形式透出。

这些数据在刷新后也会一起恢复。

### 模型选择弹窗的搜索与分组

「模型管理 → 添加模型」、自定义模型的「选择渠道模型」和令牌的「模型权限」共用同一个弹窗，支持按模型名
模糊搜索（渠道 ID、上游模型名和提供商名称都能匹配），没有命中的分组会自动隐藏。弹窗可以在「按渠道分组」
和「按提供商分组」之间切换，两种视图分别记住折叠状态；点分组标题可以折叠/展开，也可以一键
「展开全部 / 折叠全部」。

搜索状态下「全选可添加」只会选中当前可见的条目，不会误选被过滤掉的内容；折叠只是显示状态，不影响分组
全选与已选统计。令牌的模型权限只列出「模型管理」里已启用的模型，没有渠道的自定义模型归到
「自定义模型」分组；勾选结果会合并到令牌编辑弹窗里手动填写的模型名中，下方的模型徽章实时预览，点击模型名即可复制。

令牌的模型权限也可以直接手填模型名，每行一个或用逗号、分号分隔，支持 `*` 通配符：`*` 匹配任意长度（包括空）
且能跨过 `/`，例如 `*deepseek*` 匹配所有名字里带 deepseek 的模型（包括带渠道前缀的），`deepseek*` 只匹配
以 deepseek 开头的模型，单独一个 `*` 表示全部模型。留空同样表示可以使用全部模型。

### 输出速度与思考长度

「调用日志」的列按「输入 / 输出 / 耗时」三段组织：

| 列 | 主值 | 下方明细 |
| --- | --- | --- |
| 模型 | 模型 ID + 流式/重试标签；命中模型亲和时右上角有橙色星标 | 本次实际命中的渠道模型（形如 `A/think`） |
| **输入** | 输入 token 总量 | 命中提示词缓存的部分（`缓存读 N`，没命中则不显示） |
| **输出** | 输出 token 总量 | 思考 token（`思考 N`，上游未上报时退回显示字符数）、输出速度 |
| **耗时** | 总耗时 | 首字耗时（仅流式有）、本次请求的总 token |

日志工具栏的「单位」开关（默认开启）会把 Token 数缩写为 K / M / B，鼠标悬停仍能看到精确值；关掉后恢复完整数字。
状态筛选除了「成功 / 失败」，还可以选「有重试」：只显示发生过重试的请求，不区分最终成功还是失败。

失败记录的状态码徽章可以点击查看「错误信息」：上方概要列出请求模型、渠道模型、渠道和状态码，下面分成两个独立区块——「错误详情」是调用方实际收到的内容（上游错误会原样展示），「内部原因」只用于后台排查，可能包含渠道、上游地址等细节。

多 Key 渠道的日志会在渠道列下方显示本次最终使用的 Key：紧凑彩色徽章里的 `#序号`，有备注时跟在序号后面（例如 `#2 备用账号`），没有备注时显示 `#3（无备注）`。命中 Key 亲和时徽章右上角有橙色星标。带重试的日志会显示「重试 N」徽章，点开后先看到按「渠道 + 上游模型」分行的重试信息（同一渠道的不同上游模型不会合并）；如果某个渠道内换过多个 Key，再点该行的「Key 重试」继续下钻，查看每次 Key 尝试的状态码、耗时和错误，Key 同样以 `#序号 + 备注` 显示，命中亲和的那次尝试也会带星标。

速度的分母用的是**生成耗时**而不是总耗时——首字之前的排队和建连时间不应该算进生成速度，所以流式请求
按「总耗时 − 首字耗时」计算。**非流式请求是一次性返回的，没有有意义的生成窗口，因此首字和速度都不显示，
只保留总耗时。**

思考用量优先用上游单独上报的数值（OpenAI 的 `completion_tokens_details.reasoning_tokens`、
Gemini 的 `thoughtsTokenCount`）；上游没上报时退回显示思考内容的字符数（`思考 N 字`）。
Anthropic 把思考算在 `output_tokens` 里，所以那一栏会显示字符数。

缓存命中同样从各家不同字段归一化：OpenAI 的 `prompt_tokens_details.cached_tokens`、
DeepSeek 的 `prompt_cache_hit_tokens`、Anthropic 的 `cache_read_input_tokens`、
Gemini 的 `cachedContentTokenCount`。

## 常见问题

**Q：为什么配好了渠道，调用还是提示模型不存在？**
模型需要在「模型管理」里手动添加一次。这是刻意设计的，避免渠道里填的上游模型名被意外暴露出去。

**Q：一个渠道下能填多少个模型？**
不限制。只有被添加进「模型管理」的那些才会对外开放，其余只是候选。

**Q：上游不是 OpenAI 协议怎么办？**
渠道类型选 Anthropic 或 Gemini，网关会做协议转换。其它协议可以先看看是否兼容 OpenAI（绝大多数国内服务商都兼容）。

**Q：自定义模型的路由是负载均衡还是故障转移？**
默认是**顺序故障转移**——永远优先用第一个，只有它挂了才往下走。想分摊流量就把策略改成「轮询均衡」。

**Q：删除了渠道，模型管理里的模型为什么还在？**
删除渠道默认只删除渠道本身，模型配置会保留并标记为「渠道模型不存在」或「渠道已禁用」，方便之后重建同名渠道或调整路由。需要一起清理时，可以在删除确认框里选择「删除并移除模型」，也可以在模型管理里手动删除。

**Q：调用返回「模型暂不可用」，但日志里有更详细的原因？**
对外错误只说明模型不可用，不会暴露渠道 ID、渠道状态或上游地址；具体是哪个渠道、什么原因只记录在调用日志里。上游自己返回的错误会原样透传。

**Q：数据存在哪里？怎么备份？**
`data/ldmapi.db`（bbolt 单文件数据库）。停止服务后直接复制这个文件即可；也可以在「系统设置 → 备份导出」里勾选需要的内容，导出一份 JSON 到服务器的 `data/backups/` 目录。备份文件包含明文上游 Key 和 API 密钥，因此只写入服务器本地、不通过浏览器下载，请妥善保管。

**Q：忘记管理密码了？**
用 `-password 新密码` 启动一次即可重置。

## 从源码构建

需要 Go 1.24 或更高版本。

```bash
git clone <repo> && cd ldmapi
go build -o ldmapi .
```

交叉编译：

```bash
# Windows
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o dist/ldmapi-windows-amd64.exe .

# Linux
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o dist/ldmapi-linux-amd64 .
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags "-s -w" -o dist/ldmapi-linux-arm64 .
```

Windows 产物的图标和版本信息来自 `assets/ldmapi.ico`，由 `go-winres` 生成 `rsrc_windows_*.syso`，`go build` 会自动链接。仓库里已包含生成好的 syso；更新图标后重新生成：

```bash
go install github.com/tc-hib/go-winres@latest
go-winres simply --arch amd64,arm64 --icon assets/ldmapi.ico \
  --product-name "懒大猫 API" --file-description "懒大猫 API - 模型聚合网关" \
  --product-version 1.13.0 --file-version 1.13.0 --original-filename ldmapi.exe
```

修改前端时不必重新编译，让程序直接从磁盘读取前端资源即可：

```bash
LDMAPI_DEV=web go run . -port 3000
```

## 安全提示

- 默认密码是 `landamao`，**首次登录后请立刻修改**。登录接口按客户端 IP 限制为每 10 分钟最多 10 次尝试，密码错误时响应会延迟 2 秒。
- 网关默认只监听 `127.0.0.1`。如果需要局域网或公网访问，显式传 `-host 0.0.0.0`，并建议放在 Nginx / Caddy 之后，或加防火墙规则。
- 管理接口只接受登录会话 Cookie，API 密钥只能调用模型相关端点，无法访问管理接口或文件、微调、批处理等账号级上游接口。
- 管理端的写请求会校验 `Origin` / `Referer` / `Sec-Fetch-Site`，只接受同源页面发起，跨站页面无法借登录态提交操作；`/api` 不返回 CORS 头，只有对外的 `/v1` 接口允许浏览器跨域调用。
- 修改管理密码会立即让此前签发的所有登录会话失效。
- 上游渠道的 API Key 以明文保存在本地数据文件中，请确保该文件权限正确（默认 `0600`）；保存渠道的接口响应只返回脱敏后的密钥。
- 对外错误只返回模型级结论，不包含渠道 ID、渠道状态与上游地址；上游原始错误会原样透传，详细原因记录在调用日志中。
